# 1. Product vision

Build a personal AI-assisted job-search operating system that continuously finds suitable roles, filters them against Roshan's actual experience and Irish work eligibility, scores them for relevance, generates ATS-friendly application materials, and prepares applications for human review.

The system must optimize for **quality, accuracy, and strategic fit**, not maximum application volume.

It must never operate as a reckless mass-application bot.

The user should remain in control of:

- Final job selection
- Final CV review
- Salary answers
- Immigration/work-permission answers
- Screening-question answers
- Application submission
- Any networking or recruiter outreach

The system should automate repetitive research and preparation while preserving truthful, evidence-backed applications.

# 9. Eligibility and targeting rules

## 9.1 User-controlled eligibility configuration

```json
{
  "location": "Dublin, Ireland",
  "current_permission": "Stamp 1G",
  "can_work_full_time_now": true,
  "requires_employment_permit_now": false,
  "requires_future_sponsorship": true,
  "preferred_long_term_path": "Critical Skills Employment Permit",
  "allowed_locations": [
    "Dublin",
    "County Dublin",
    "Ireland",
    "Remote within Ireland",
    "Hybrid within commuting distance"
  ],
  "excluded_locations": [
    "UK only",
    "US only",
    "EU residence required outside Ireland"
  ],
  "preferred_employment_types": [
    "Permanent",
    "Fixed-term"
  ],
  "excluded_employment_types": [
    "Unpaid",
    "Commission only"
  ]
}
```

Do not hardcode salary thresholds in the first version. Store them in configurable settings because permit rules and personal preferences may change.

## 9.2 Work-permission classification

Each job should receive:

- `eligible_now`
- `likely_eligible_now`
- `unclear`
- `not_eligible`

And separately:

- `long_term_sponsorship_promising`
- `long_term_sponsorship_possible`
- `long_term_sponsorship_unlikely`
- `unknown`

Do not automatically reject every job saying “no sponsorship.”

Instead distinguish:

- Sponsorship not required at start
- Sponsorship required in the future
- Employer explicitly refuses any future permit support
- Employer statement ambiguous

## 9.3 Hard rejection rules

Reject when:

- Job is clearly outside allowed geography
- Explicit work authorization requirement cannot be met
- Unpaid or commission-only
- Clearly internship-only where graduate role is not acceptable
- Role is director, head, principal, staff, or similarly senior without exceptional evidence
- Role requires a regulated credential Roshan does not hold
- Role requires deep ML research, model training, or PhD-level expertise
- Role is unrelated to enabled career profiles
- Listing is expired
- Listing is a duplicate already reviewed
- Job is fraudulent or suspicious

## 9.4 Soft penalties

Penalize but do not automatically reject:

- 3–5 years requested
- Missing one cloud platform
- Missing one framework where transferable experience exists
- Salary not disclosed
- “No sponsorship” where current work authorization may still allow employment
- Role title is adjacent rather than exact

# 10. Job scoring model

Each job receives a score out of 100.

## Recommended weighting

| Factor | Weight |
|---|---:|
| Skills overlap | 22 |
| Evidence strength | 18 |
| Project relevance | 15 |
| Seniority fit | 12 |
| Current work eligibility | 12 |
| Long-term permit potential | 8 |
| Location and work mode | 5 |
| Salary compatibility | 4 |
| Career-direction alignment | 4 |

## Score bands

- **85–100:** Priority application
- **75–84:** Strong match
- **65–74:** Worth reviewing
- **50–64:** Low priority / stretch
- **Below 50:** Reject or archive

A hard disqualifier overrides the numerical score.
